# A6.11 Index every protocol draft, and fail CI when one is left out

A task of Loom's A6 block, the Tapestry connector, from P-19. This is its plan.

The Tapestry connector's `tapestry_guide` serves a file in `protocols/drafts/` or `protocols/nips/` only once `protocols/README.md` links it from its Spec index. A file left out is invisible to every teammate's Claude. On staging, 3 of the 24 drafts were left out: `filters-on-dlists`, `search-over-tags` and `treasure-map`.

## What it changes

- **Two new rows in the Spec index:**
  - `filters-on-dlists`, 📝 pre-NIP. A stub that proposes a `dlists` filter field beside `kinds`.
  - `search-over-tags`, 💭 idea. An overview with no wire format yet.

  David wrote both here in September 2026.
- **A new "Not in the index" section** in the README, listing the files left out on purpose, each with why. It is a `##` section of its own, because the connector reads every table row in the Spec index section as a topic. Its first row is `treasure-map`. That is David's first draft of how a Treasure Map assigns Trusted Lists and DList items to Assistants (Sept 20 to 22). It has been superseded by `treasure-maps`, the working spec begun Sept 27, which doesn't cite it.
- **`test/protocols-index.test.js`**, a new suite in the test gate, run on every pull request by `.github/workflows/test.yml`. It fails if:
  - a file in `drafts/` or `nips/` is neither in the Spec index nor in "Not in the index";
  - a file is in both;
  - either section links a file that isn't there;
  - a left-out row gives no reason.

  It reads each row's first protocol link, as the connector does.

## Done when

The three are indexed or listed with a reason, the suite runs in `npm test`, and the connector lists `protocols/filters-on-dlists` and `protocols/search-over-tags` from staging.

That `treasure-map.md` is superseded by `treasure-maps.md`, and that nothing in it is missing from the newer spec.
